# Persistence mode matrix

- Source: Area 8 — mode matrix and round trips

The matrix includes flags and choices that change authoritative shape,
backup/recovery availability, or interchange bytes. It excludes UI/request flags
whose only persisted effect is their own scalar value.

## Complete matrix

| Flag / mode | Storage location | What diverges | Both-states risk | Both-transitions risk |
|---|---|---|---|---|
| `db.optimizePluginMemory` | Flag in `database/database.bin`; off: `db.pluginCustomStorage` + `db.pluginStorageMeta`; on: `pluginsave/*.json` + `pluginsave-meta/*.json` | Inline reactive map vs on-demand KV; optimized reads opt into the resource cache | Off is exposed to reactive/clone boundaries; on needs separate rows and disables legacy plugins | off→on writes KV before deleting inline; on→off saves inline before deleting KV (`pluginSaveStorage.ts:182-316`). The copied values are equal during either transition, but a snapshot made in the just-disabled window is unmarked and does not later replace the external row set (confirmed finding) |
| Browser resource cache | Opt-in `localStorage['pocketrisu-resource-cache']`; bytes/manifests in IndexedDB `pocketrisu-resource-cache-v1` | DB segments, chats, and cached KV reads can use content-addressed local bytes | Off always reads server; on may serve only a server-confirmed hash and verifies bytes | Disable removes opt-in, bumps epoch, drains writes, closes/deletes IDB (`resourceCache.ts:132-148,441-533`). Re-enable starts a new epoch. Cross-tab blocked deletion can leave old cache bytes, but they remain non-authoritative |
| `POCKETRISU_HUB_HOSTING` | Server environment | Hides disk stats and file-backup endpoints; pins snapshot byte cap; portable export/import, authoritative SQLite, chat backups, and spool remain | Hub has fewer server-side recovery controls, normal exposes them | normal→hub makes existing file backups temporarily invisible but does not delete them; hub→normal recreates the root and exposes them. A lower hub cap can trim old snapshots at the next rotation (`server.cjs:273-310,970-989,4971-4975`) |
| Plugin generation + `db.allowV2Plugin` | Plugin `version` in `db.plugins[]`; allow flag in DB | V2/V2.1 synchronous inline API vs V3 async iframe API | Legacy execution is unsafe/deprecated; V3 can use all three storage APIs | Optimization UI is blocked unless all enabled plugins are V3; an imported impossible combination leaves legacy plugins stored/enabled but skipped at runtime (`plugins.svelte.ts:446-467`) |
| Chat externalization | Marker `migration/chats-externalized`; `database.bin` stubs + `chats/<chaId>/<chatId>` rows | Legacy monolith vs always-externalized server runtime | Stub graph needs every referenced row; export must fold rows | Monolith→split creates a migration snapshot and atomically writes rows/stubs; split→monolith happens only in self-contained exports. Duplicate payload chats are remapped, but duplicate stubs are not—relevant to the HTML finding |
| V3 plugin storage API choice | Save: inline/KV above; local: `localStorage['safe_plugin_*']`; IDB-like persistent KV: `cache/plugin-storage/*.json`; ownership sidecars in matching backend | “save” travels with DB/backups, local/IDB are device-local | A plugin choosing local/IDB must tolerate non-travel; only save data participates in snapshots | There is no automatic backend migration; plugins must copy deliberately. Backup restore can time-skew restored save data against unchanged device-local data (`pluginStorageMeta.ts:1-18`, `pluginSafeClass.ts:50-90`) |
| `db.imageCompression` | DB flag; affects newly exported card/module asset bytes | Off preserves original bytes; on lossily re-encodes recognized non-WebP/non-AVIF images (`compressImage.ts:5-15`) | On changes byte identity/animation/metadata; off produces larger files | Transition is prospective only; it does not rewrite stored assets. The same character exported before/after toggle is not byte-round-trippable |
| `db.inlayImageLossless` | DB flag; new inlay files + sidecars under `save/inlays` | PNG lossless vs WebP quality 0.85 (`inlays.ts:460-467`) | Capacity vs irreversible quality tradeoff | Prospective only; toggling does not transcode old inlays, so one database can contain both formats safely |
| `db.saveSignatures` | DB flag; signature objects in inlay store plus `{{inlayeddata::id}}` chat tokens | Off drops provider thought signatures; on creates JSON signature inlays (`google.ts:750-760`) | On adds a second store that backups/exports must enumerate | Toggle is prospective. Upstream-target export drops these inlays while preserving tokens (finding above) |
| Generation provenance/artifact flags: `promptInfoInsideChat`, `promptTextInfoInsideChat`, `rememberToolUsage`, `outputImageModal` | DB flags; resulting `Message.promptInfo`, encoded tool markers, and image inlays live in chat rows/inlay store | Off stores ordinary response content; on adds request provenance, replayable tool results, or media references (`index.svelte.ts:218-241,1376-1451`; `request.ts:947-989`) | Larger/more sensitive chat payloads and additional cross-store references when on | Prospective only: toggles do not strip already-persisted artifacts. Generic chat/full-backup codecs retain fields, but no flag-on/off round-trip fixtures exist |
| `db.allowAllExtentionFiles` | DB flag | Picker accepts extensions outside the normal allowlist | Off limits unsupported assets; on permits arbitrary bytes/ext values | Prospective only, but on × CharX's blanket `.json` ignore is an unhandled combination (finding above) |
| Hypa V3 / `settings.useExperimentalImpl` | DB and per-preset settings; serialized `chat.hypaV3Data` | Two algorithms consume/update one serializable summary shape (`hypav3.ts:119-150,201-205`) | Algorithmic quality risk, not a separate storage backend | Both directions reuse `toHypaV3Data`; no shape migration was found. Not covered in `test/compat/` |
| `POCKETRISU_CHUNK_THRESHOLD` | Server env; physical SQLite `kv` row vs `manifest_chunks` + chunk table | Same logical value stored inline or content-defined chunks | Bad thresholds affect performance/capacity; marker resolver is shared | Existing rows can remain in either representation across restart; cross-threshold import/export/restore is covered by `db-chunking.test.ts` |
| `RISU_STREAM_INGEST_MIN_BYTES` | Server env | In-memory decode/externalize vs disk-backed streaming walker | Parser parity is the risk | Both paths normalize to the same stubs/rows; parity is covered in `stream-risu-load.test.ts:141` and large end-to-end imports in `db-chunking.test.ts` |
| `POCKETRISU_CHAT_BACKUP_DIR` | Server env; marker `save/__chat_backup_path`; version files under chosen root | Changes where chat pre-image history is written/listed | Each root works independently | A→B and B→default strand history at A (finding above) |
| Chat-backup byte cap (`config/chat-backup-max-bytes`, `POCKETRISU_CHAT_BACKUP_MAX_BYTES`) | SQLite config with env precedence | Retention depth | Higher consumes disk; lower has fewer recovery versions | Lowering the cap deliberately deletes older bundles at reconcile; it is not represented in `.bin` backups (`chatBackups.cjs:41-64,990-1004`) |
| Server backup path (`config/server-backup-path`) | SQLite config + `save/__backup_path`; files under selected directory | Current file-backup list/save/download root | Each root is usable | A→B intentionally leaves A in place (`server.cjs:901-905`), so old archives disappear from the UI until the operator revisits A; hub mode adds another visibility gate |
| Snapshot caps + `POCKETRISU_BACKUP_INTERVAL_MS` + `POCKETRISU_HUB_SNAPSHOT_CAP_MB` | Snapshot config in SQLite; interval/cap in env; snapshots under `database/dbbackup-*` | Recovery frequency/count/bytes, with hub pinning max bytes | Low limits reduce recovery depth | Reducing limits trims on the next snapshot; switching into hub can override a larger stored byte limit (`server.cjs:273-310,355-380`) |
| `POCKETRISU_SPOOL_DIR` | Server env; temporary files only | Where assembled/decoded databases are staged | Bad/unwritable root disables or fails backup assembly, not authoritative DB | Old orphan spools are swept only in the currently selected root (`server.cjs:872-899`). Critic correction: this row understates the divergence — compressed streaming loads bypass the configured root entirely and their orphans can exhaust the save volume; the boot sweep is also unsafe under a shared root. See [decoded-stream-load-spools-bypass-configured-spool-and-orphan-sweep](../warning/decoded-stream-load-spools-bypass-configured-spool-and-orphan-sweep.md) and [boot-spool-sweep-can-unlink-another-instances-active-file](../warning/boot-spool-sweep-can-unlink-another-instances-active-file.md) |
| `RISU_BACKUP_IMPORT_MAX_BYTES` | Server env | Import admitted/rejected | Zero/unset has no explicit cap; positive values reject oversized archives | Changing it affects future admission only; no stored-data migration (`server.cjs:1029,4848-4859`) |

## Backup taken in mode A and restored in mode B

| A → B | Result | Risk / evidence |
|---|---|---|
| optimize off → server/client that was on | The backup's DB flag wins. Inline storage remains inline when flag is false; stale external rows are cleared on import | Covered by `plugin-backup-entries.test.ts:264-283` |
| optimize on Node-only → fresh/off install | Archive carries independent `pluginsave/` and meta rows plus the optimized flag; import installs rows/stub DB | Covered by `plugin-backup-entries.test.ts:93-214` |
| automatic snapshot during optimize on→off → later optimized live state | Snapshot contains the older inline values, but its false flag prevents the folded-row ownership marker; restore leaves the newer live rows, which overwrite the snapshot values at boot | Confirmed disabled-snapshot warning; no regression test |
| optimize on upstream-target → upstream → Pocket | Export folds values/meta into DB; upstream can load them; Pocket re-import externalizes because flag is true | Pocket fold/re-import covered; actual upstream load/re-export is not |
| resource cache on/off → either | Cache and opt-in are not in `.bin`; destination-local choice remains. Server hash negotiation prevents old cached bytes becoming authoritative after restore | No transition integration test |
| normal ↔ hub | Portable backup format/import is identical. File backups and chat-version history are not embedded in portable `.bin` | Hub portable import/export on the same save is not tested |
| legacy monolith → externalized | Import splits it; safety/atomicity above | Strong compat coverage |
| externalized → upstream | Chats fold correctly; plugin storage folds; inlays do not travel | Inlay warning above; actual upstream executable not tested |
| plugin save/local/IDB backend | Only “save” travels. `safe_plugin_*`, `cache/plugin-storage/*`, and their local owner sidecars remain device-local | Intentional API distinction, but no backup-mode test documents it |
| image compression/lossless-inlay A → B | Flags travel in DB, but already-created bytes remain in their existing encoding; subsequent exports/writes use restored flag | No cross-mode byte/semantic fixture |
| chunk threshold low ↔ high | Portable backup exposes logical bytes and destination stores according to its threshold | Covered by `db-chunking.test.ts` |
| chat-backup root/cap A → B | Version history is outside `.bin`; root transition can hide it and cap reduction can trim it | Finding above; no end-to-end root transition test |
